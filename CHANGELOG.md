## [2.0.0] - 2026-02-09

### ⚠️ BREAKING CHANGES

#### Table CSS Selectors Changed to BEM Methodology

**What Changed:**
- Table CSS selectors have been refactored from descendant selectors to proper BEM naming convention
- Old: `.text-block-content table`, `.text-block-content td`, `.text-block-content th`
- New: `.text-block-content__table`, `.text-block-content__table-cell`, `.text-block-content__table-cell--header`

**Why This Change:**
This change aligns the table styling with the project's Constitution Principle V (BEM Methodology) and provides better CSS specificity, avoiding conflicts with global styles.

**Migration Guide:**

If you have **custom CSS** that targets tables generated by this tool, you need to update your selectors:

**Before (v1.x):**
```css
/* Old descendant selectors */
.text-block-content table {
  border-collapse: collapse;
}

.text-block-content td {
  padding: 12px;
}

.text-block-content th {
  background-color: #f0f0f0;
}

.text-block-content tr:hover {
  background-color: #f9f9f9;
}
```

**After (v2.0):**
```css
/* New BEM selectors */
.text-block-content__table {
  border-collapse: collapse;
}

.text-block-content__table-cell {
  padding: 12px;
}

.text-block-content__table-cell--header {
  background-color: #f0f0f0;
}

.text-block-content__table-row:hover {
  background-color: #f9f9f9;
}
```

**Complete Selector Mapping:**

| Old Selector (v1.x) | New Selector (v2.0) |
|---------------------|---------------------|
| `.text-block-content table` | `.text-block-content__table` |
| `.text-block-content thead` | `.text-block-content__table-head` |
| `.text-block-content tbody` | `.text-block-content__table-body` |
| `.text-block-content tr` | `.text-block-content__table-row` |
| `.text-block-content th` | `.text-block-content__table-cell--header` |
| `.text-block-content td` | `.text-block-content__table-cell` |
| `.text-block-content thead tr` | `.text-block-content__table-row--header` |

**Who Is Affected:**
- Projects with **custom CSS overrides** for tables
- Sites that use **CSS specificity hacks** to override table styles
- Integration tests that **assert on CSS class names**

**Who Is NOT Affected:**
- Users who rely solely on the **default configuration** (no migration needed)
- Sites that **don't override** table styling
- Users who only use the **--config flag** for styling (no code changes needed)

**Testing Your Migration:**
1. Update your custom CSS selectors using the mapping table above
2. Generate HTML with v2.0: `privacy-notice-gen document.docx --preview > test.html`
3. Open `test.html` in your browser
4. Verify tables render correctly with your custom styles
5. Test at all breakpoints (mobile, tablet, desktop)

### ✨ Added

#### New Table Styling Features
All new features are **opt-in** (disabled by default) to maintain backward compatibility:

1. **Interactive Row Highlighting** (`hoverHighlight` & `hoverColor`)
   - Add hover effects to table rows for better usability
   - Automatically validates WCAG 2.1 AA contrast for hover color
   ```yaml
   tables:
     hoverHighlight: true
     hoverColor: "#f0f8ff"  # Light blue hover
   ```

2. **Rounded Corners** (`roundedCorners` & `borderRadius`)
   - Modern visual styling for tables
   ```yaml
   tables:
     roundedCorners: true
     borderRadius: 8
   ```

3. **Compact Mobile Padding** (`compactMobile` & `mobilePadding`)
   - Reduce padding on mobile devices for better space utilization
   ```yaml
   tables:
     compactMobile: true
     mobilePadding: 8
   ```

4. **Responsive Card Layout** (`responsiveStacking`)
   - Transform tables into card-based layout on mobile
   - Uses `data-label` attributes to show column headers inline
   ```yaml
   tables:
     responsiveStacking: true
   ```

5. **Sticky Table Headers**
   - Table headers remain visible while scrolling long tables
   - Enabled automatically for all tables

6. **Automatic `<tbody>` Wrapping**
   - Prevents browser auto-generation issues
   - Ensures consistent DOM structure

## [1.0.0] - 2026-01-29

### Initial Release

#### Features
- Convert .docx files to semantic HTML fragments
- WCAG 2.1 AA compliant output
- BEM-scoped CSS (`.text-block-content`)
- Responsive design (5 breakpoints: 375px - 1200px)
- Configurable styling via YAML/JSON
- CLI with exit codes for CI/CD integration
- Preview mode for browser testing
- Table horizontal scrolling on mobile
- Striped table rows
- Proper heading hierarchy validation

#### Requirements
- Node.js 20.x LTS or higher
- .docx file format (Word 2007+)
- Maximum file size: 1MB
